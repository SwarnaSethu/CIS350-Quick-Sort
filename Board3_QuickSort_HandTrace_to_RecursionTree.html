0 — What Is Quick Sort?

Start with the idea before looking at the code.

1

One pivot, two parts

  • Choose one value as the pivot.
  • Partition the current range so values smaller than the pivot are on its left and values larger are on its right.
  • The pivot is now in its final position.
  • Repeat the same process on the left part and the right part.
2

Our example

For today's version, the last value is the pivot.
[5, 1, 4, 2, 8, 3] → partition around 3 → [1, 2] | 3 | [5, 8, 4]
3

What Quick Sort guarantees after one partition

  • The pivot is in the position it will have in the final sorted array.
  • Everything left of it is smaller; everything right of it is larger.
  • We do not claim that either side is sorted yet.
  • That is the key idea we will trace by hand first.

The mental model

Partition one range → fix one pivot → recursively sort the two remaining ranges.

  • Pivot = a[high] = 3.

2

Ask one question at j

Is a[j] < pivot?
  • NO: leave the value where it is; move on.
  • YES: move the smaller-zone boundary i one step right, then swap.

Hand-trace rule

  1. Mark low, high, pivot, and i.
  2. Move j one position at a time.
  3. Only when a[j] < pivot do we increase i and swap.
  4. When j finishes, swap the pivot into i + 1.

What we have discovered

  • Partition does one scan.
  • i is not a second scanner; it marks the end of the smaller zone.
  • The pivot's final position comes from i + 1.

3 — From the Hand Trace to Pseudocode

Do not memorize the code. Translate each action we just traced into one algorithm step.

1

What did we do by hand?

  1. Choose the last value as the pivot.
  2. Set i = low − 1.
  3. Let j scan from low to high − 1.
  4. If a[j] < pivot, increase i and swap a[i] with a[j].
  5. After the scan, swap the pivot with a[i + 1].
  6. Return i + 1 as the pivot position.
That becomes our Partition pseudocode.
PARTITION(a, low, high)
    pivot ← a[high]
    i ← low − 1

    FOR j ← low TO high − 1
        IF a[j] < pivot
            i ← i + 1
            SWAP(a[i], a[j])

    SWAP(a[i + 1], a[high])
    RETURN i + 1
2

What did we do after partition?

  • The first partition returned p = 2.
  • So we sorted 0..1 and 3..5.
  • Each of those calls follows the same rule.
  • That is recursion: the method calls itself on smaller ranges.
Now translate that into recursive pseudocode.
QUICKSORT(a, low, high)
    IF low < high
        p ← PARTITION(a, low, high)

        QUICKSORT(a, low, p − 1)
        QUICKSORT(a, p + 1, high)
Base case: if low ≥ high, there is nothing to partition.

Notice the order

We did not invent the recursive code first. The hand trace showed us the smaller ranges. The pseudocode simply records the pattern we discovered.
Heads up

There are different ways to partition

  • Today we are using the Lomuto partition scheme: the pivot starts at the end, j scans the range, and i marks the boundary of the smaller values.
  • Hoare partition: instead of one forward scan, two pointers start near the two ends and move inward. They look for values on the wrong side and swap them. Hoare returns a split boundary; that boundary is not necessarily the pivot's final position.
  • So do not memorize one partition routine as “the” Quick Sort. Quick Sort is the overall algorithm; Lomuto and Hoare are partition schemes. The recursive idea is still: partition the range, then sort the two resulting parts.
Think of it this way: Lomuto = one boundary + one scan. Hoare = two pointers moving inward. Both are ways to do the partition step.

7 — Write It: The Recursive QuickSort

Partition, then do the same on the left side and on the right side

    static void QuickSort(int[] a)
    {
        QuickSort(a, 0, a.Length - 1);
    }
 
    static void QuickSort(int[] a, int low, int high)
    {
        if (low < high)
        {
            int p = Partition(a, low, high);
            QuickSort(a, low, p - 1);
            QuickSort(a, p + 1, high);
        }
    }
  • There are two methods named QuickSort. C# allows this when the parameters differ. It is called overloading.
  • QuickSort(int[] a) takes only the array. It calls the second method with the whole array: QuickSort(a, 0, a.Length - 1).
  • QuickSort(int[] a, int low, int high) sorts positions low to high, and it calls itself.
  • Base case: if (low < high). A part with one value, or none, does nothing and the calls stop.
  • Otherwise Partition places the pivot at p. Then we sort everything left of p and everything right of p. The pivot at p is never touched again.
  • Visual Studio underlines Partition: CS0103, the name does not exist yet. We wrote the call we wish we had. Writing Partition is the next step.

8 — Write It: Partition, the Setup

The pivot, the boundary of the smaller zone, and the sweep

    static int Partition(int[] a, int low, int high)
    {
        int pivot = a[high];
        int i = low - 1;
 
        for (int j = low; j < high; j++)
        {
            // is a[j] smaller than the pivot?
        }
 
        // put the pivot in its place
        return 0;   // temporary
    }
  • Partition works on positions low to high and returns the position where the pivot ends up.
  • The pivot is the last value, a[high].
  • i is the last position of the smaller zone. The zone starts empty, so i is low - 1, one step before the part.
  • j sweeps from low up to, but not including, high. The pivot itself is not compared with itself.
  • The temporary return 0; keeps the method compiling for now. The squiggle under Partition in QuickSort is gone.

9 — Write It: Partition, the Sweep and the Landing

Grow the smaller zone, then drop the pivot in right after it

    static int Partition(int[] a, int low, int high)
    {
        int pivot = a[high];
        int i = low - 1;
 
        for (int j = low; j < high; j++)
        {
            if (a[j] < pivot)
            {
                i++;
                Swap(a, i, j);
            }
        }
 
        Swap(a, i + 1, high);
        return i + 1;
    }
  • If a[j] is smaller than the pivot, the smaller zone grows by one: i++.
  • Then Swap(a, i, j) brings that small value into the zone. The value that was there goes out to position j.
  • If a[j] is not smaller, we do nothing. The sweep just moves on.
  • After the sweep, positions low to i hold all the smaller values.
  • The pivot swaps with the value right after them, i + 1. That is its final place, and we return it.
  • Visual Studio underlines Swap: CS0103, it does not exist yet. We write it next.
  • Key reasoning: i tells us the last index occupied by a smaller value. Therefore the pivot's landing position is always i+1.
  • That is why the code does not guess a position. It computes the position from the boundary created by the scan.

10 — Write It: A Swap Helper

Quick Sort swaps in two places, so we write the swap once

    static void Swap(int[] a, int x, int y)
    {
        int temp = a[x];
        a[x] = a[y];
        a[y] = temp;
    }
  • Partition calls Swap twice: in the sweep, and when the pivot lands.
  • So the three temp lines go into one small method. It takes the array and the two positions to swap.
  • It is the same temp idea as in Bubble Sort.
  • The squiggle under Swap is gone. Run the program:
  • Before: 5, 1, 4, 2, 8, 3 then After: 1, 2, 3, 4, 5, 8.

11 — The Whole Program

Everything together: Program.cs

using System;
 
class Program
{
    static void Main()
    {
        int[] list = { 5, 1, 4, 2, 8, 3 };
 
        Console.WriteLine("Before: " + string.Join(", ", list));
        QuickSort(list);
        Console.WriteLine("After:  " + string.Join(", ", list));
    }
 
    static void QuickSort(int[] a)
    {
        QuickSort(a, 0, a.Length - 1);
    }
 
    static void QuickSort(int[] a, int low, int high)
    {
        if (low < high)
        {
            int p = Partition(a, low, high);
            QuickSort(a, low, p - 1);
            QuickSort(a, p + 1, high);
        }
    }
 
    static void Swap(int[] a, int x, int y)
    {
        int temp = a[x];
        a[x] = a[y];
        a[y] = temp;
    }
 
    static int Partition(int[] a, int low, int high)
    {
        int pivot = a[high];
        int i = low - 1;
 
        for (int j = low; j < high; j++)
        {
            if (a[j] < pivot)
            {
                i++;
                Swap(a, i, j);
            }
        }
 
        Swap(a, i + 1, high);
        return i + 1;
    }
}

12 — Worst Case: A Sorted List

With the last value as pivot, a sorted list splits as badly as possible

Sorted list [1, 2, 3, 4, 5]
CallPivotComparisonsPivot landsArray after
QuickSort(a, 0, 4)54position 4[1, 2, 3, 4, 5]
QuickSort(a, 0, 3)43position 3[1, 2, 3, 4, 5]
QuickSort(a, 0, 2)32position 2[1, 2, 3, 4, 5]
QuickSort(a, 0, 1)21position 1[1, 2, 3, 4, 5]
  • The pivot is the biggest value every time, so every other value is smaller and goes into the smaller zone.
  • The pivot lands at the far right. The left part is only one value shorter than before. The right part is empty.
  • So we make n − 1 partitions, with n − 1, n − 2, … 1 comparisons: 4 + 3 + 2 + 1 = 10.
  • That is n(n − 1) / 2: O(n²), as slow as Selection Sort.
  • A reverse-sorted list does the same thing: the pivot is always the smallest.

How did we get the numbers? A part with m values makes m − 1 comparisons: every value is compared with the pivot except the pivot itself. Multiply by the number of parts at that level.
pivot of a partpivot already in final placeone value: stops
  • Start with 15 values. The first pivot lands in the middle, so two parts of about n / 2 remain.
  • Each of those splits into parts of about n / 4, then n / 8, and so on, until a part has 1 value.
  • Halving 15 values takes 4 levels to reach 1. In general, the number of levels is log₂ n.
  • At each level, every value is compared with its part's pivot about once: about n comparisons per level.
  • Here: 14 + 12 + 8 + 0 = 34 comparisons, against 15 × 14 / 2 = 105 for Selection Sort.
  • Total: n × log₂ n, which is O(n log n). For 1,024 values: about 10,240 against 523,776.

14 — Choosing the Pivot

The last value is easy to code, but a sorted list punishes it

1

Last value

  • What we coded. Simple.
  • Worst case on sorted or reverse-sorted lists, which are common in real data.
2

Random value

  • Swap a random value into the last place, then partition as before.
  • No particular input is always bad.
3

Median of three

  • Look at the first, middle and last values. Use the middle one in size as the pivot.
  • Fixes sorted and reverse-sorted lists.
  • Only one line changes: how we pick pivot and move it to a[high]. The rest of Partition stays the same.
  • A bad pivot gives O(n²). A good pivot gives O(n log n). Real libraries pick the pivot carefully for this reason.

Heads up

What does “stable” mean?

  • A sorting algorithm is stable if equal-valued items keep their original relative order.
  • Example: 5A, 2, 5B should finish as 2, 5A, 5B if the sort is stable.
  • Quick Sort is generally not stable because its swaps can move equal values past one another.
  • On 6 values the difference is small. It grows fast: for 1,024 values, about 10,240 comparisons against 523,776.
  • The sorted list is the one place where Quick Sort with the last pivot is no better than Selection Sort, and Bubble Sort wins.
  • Quick Sort rearranges values by long swaps, so equal values can change order: it is not stable.

16 — Check Yourself

Answer each one before opening the answer

Q1. What is the pivot, and where does it end up after a partition?
Answer: The pivot is the value we split around. After the partition it is in its final sorted place, with smaller values on its left and bigger values on its right.
Q2. Why does QuickSort stop when low < high is false?
Answer: Then the part has one value or none. It is already sorted, so there is nothing to do. This is the base case of the recursion.
Q3. Which list is the worst case when the pivot is the last value, and how many comparisons does it need?
Answer: An already sorted list (or a reverse-sorted one). Each partition removes only one value, so it needs n(n − 1) / 2 comparisons: O(n²).
Q4. Why is the best and average case O(n log n)?
Answer: Each level of calls does about n comparisons in total, and balanced splits give about log n levels.
